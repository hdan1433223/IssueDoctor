# AI 使用说明

## 开发过程

生成式 AI 用于需求拆解、代码草拟、测试用例设计、文档结构和缺陷排查。所有修改均在本地仓库
中复核，并通过阶段测试、静态检查、真实公开仓库只读案例和安全边界检查。第三方实现只用于
学习公开架构；没有复制来源不明或许可证不兼容代码。

## 运行时

- 健康总分和 20 个指标由版本化确定性规则计算，LLM 不参与打分。
- 相似 Issue 候选默认使用自研的纯 Python 字符 n-gram 哈希 TF-IDF，不依赖任何第三方数值库；
  启用可选能力 `vector` 后改用本地 `BAAI/bge-small-zh-v1.5`，失败时自动回退到内置后端。
- 可选 OpenAI-compatible LLM 只为规则筛选样本提供类型、缺失信息与证据解释。
- Prompt 版本为 `issue-batch-v2`，输入按批处理（每批最多 8 条、14,000 字符），输出通过
  Pydantic 校验并缓存。
- 没有 LLM Key 时 BASIC 模式保留完整核心诊断。

AI 输出不会直接执行 GitHub 写操作。治理文件需通过路径/YAML/Markdown 校验，用户查看 Diff 并
确认后才会创建新分支 PR；Label 操作另行确认。验证方式包括证据链接回溯、AI 覆盖率、批次失败
计数、人工标注流程和确定性规则对照。

## 可选依赖与降级

核心诊断不依赖任何重型第三方库，安装体积约 30 MB。可选能力缺失时系统自动降级并在界面标注
启用方式，不会中断分析：

| 能力 | 缺失时的行为 |
| --- | --- |
| `vector`（本地语义向量） | 使用自研内置相似度后端，功能不缺失 |
| `pdf`（服务端 PDF 导出） | 使用网页报告页的浏览器打印导出 |
