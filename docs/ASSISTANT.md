# 报告知识助手

## 定位

报告知识助手用于解释已经生成审计报告，不直接操作 GitHub。它适合回答：

- 总分和六维分数为什么这样；
- 哪些指标和 Finding 最需要优先处理；
- 某个 Issue 的证据、缺失信息和建议动作；
- 是否存在相似或重复问题；
- 当前治理方案会生成哪些文件和 Label；
- 本次分析的数据范围、AI 覆盖率和降级限制。

它不用于读取报告之外实时变化的仓库状态。需要最新状态时应重新执行审计。

## 知识库边界

每次 `AnalysisRun` 有独立知识库和索引指纹：

- `assistant_knowledge_bases`：索引版本、源数据指纹、知识块数量和构建时间；
- `assistant_knowledge_chunks`：标题、纯文本内容、稀疏向量、来源元数据和跳转链接。

来源类型包括 `overview`、`dimension`、`finding`、`issue`、`ai_analysis`、`evidence`、
`duplicate`、`governance` 和 `guide`。问答接口在检索时必须带当前 `run_id`。

## 检索与生成

默认检索不依赖第三方向量库：

1. 对标题和正文计算稳定的字符 2-gram/3-gram 哈希特征；
2. 识别 D1–D6、M1.1–M6.3、AI 指标和 `#Issue` 编号并提高精确匹配权重；
3. 根据“总结、优先处理、证据、重复、指标定义”等问题意图调整内容类型权重；
4. 最多选取 4 个去重来源，上下文总量限制为 3,400 字符；Finding 会附带由证据关联的 Issue 编号；
5. 配置 LLM 时要求以 `[K1]` 等来源编号作答，输出通过 Pydantic 校验；
6. 无 LLM 或模型调用失败时返回检索片段和来源，不中断页面使用。

## 安全约束

- Issue、PR、评论和治理文本始终作为不可信数据，不能改变系统任务。
- 助手没有 GitHub 写权限，也不能调用治理 PR、Label 或删除接口。
- 问题最多 2,000 字符，历史最多使用最近 4 条，每条截断至 500 字符。
- 模型输出在前端使用 `textContent` 渲染，不把回答解释为 HTML。
- 外部来源链接只接受本地报告路径或 `https://github.com/` 地址。
- 仅把检索到的必要片段发送给已配置的 LLM，不发送 Token 或 API Key。

## 界面交互

- 桌面端对话面板默认约 `520 × 740` 像素，并受当前视口大小约束；移动端最多使用 92% 的屏幕高度。
- 悬浮球支持鼠标和触摸拖动，位置会保存在当前浏览器；窗口缩放或重新进入页面时会自动限制在可视区域内。
- 聚焦悬浮球后可用 `Shift + 方向键` 每次移动 20 像素。轻点仍然用于打开面板，移动超过 5 像素不会误触发打开。
- 问答记录按 `analysis_run_id` 保存到浏览器 `sessionStorage`，同一标签页内跨报告页面保留；
  关闭标签页后自动清除，不同报告之间不会串话。面板右上角可手动清空记录。

## 降级行为

- 未配置 LLM：返回 `mode=extractive` 和报告引用。
- LLM 请求失败：返回带 `llm_error.code` 的规则摘要，并提示在设置页检查鉴权、限流、
  Base URL 或模型名称。
- 索引尚未建立或源数据变化：提问时自动重建；治理包更新也会刷新索引。
- 分析任务尚未成功完成：接口返回 `ASSISTANT_REPORT_NOT_READY`。
- 索引构建失败：原审计报告仍可用，不影响导出、历史记录和治理。
